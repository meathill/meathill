# 全链路文章撰写与多平台内容创作 SOP (Omnichannel Article Writing SOP)

本文档定义了独立开发者、工作室与创作者在产出**高品质技术文章、封面资讯、产品教程及社交媒体分发物料**时的全链路标准作业流程（SOP）。旨在确保内容兼具**深度立意、读者视角、严密事实、多语言覆盖与极高视觉转化率**。

---

## ⚡ 核心理念与立意原则 (Editorial Philosophy)

1. **彻底站在读者与用户立场**：
   - 我们的文章不是厂商的公关稿，更不是未经推敲的通稿搬运。
   - 读者追求高性价比、寻找便宜甚至免费的可用工具，是完全正当合理的诉求；
   - 面对厂商借“神秘代号”、“限时免费”或“概念包装”转嫁测试成本、交付劣质半成品或侵犯隐私的行为，必须敢于揭露真相，指出核心痛点；
   - 永远算清开发者的“隐性账本”：排错时间、心流被打碎的代价，往往远超几分钱的 Token 成本。
2. **给出真正靠谱的正规军方案**：
   - 在指出问题与避坑的同时，必须为读者提供经过验证、稳定可靠、性价比优秀的替代选择。
3. **言之有物，拒绝废话**：
   - 杜绝为了凑字数而堆砌通用概念。每一小节必须有明确的结论、事实依据或代码示例。

---

## ⚡ 核心执行流（一览表）

| 阶段 | 核心任务 | 交付产物 / 规范 |
| :--- | :--- | :--- |
| **1. 事实核查 (Fact-Check)** | 抓取一手推文/官方公告/代码，提取 1:1 准确规则 | 严禁脑补；核实适用人群、接口形态、清零节点与限制 |
| **2. 中文初稿撰写** | 结构化撰写核心要点、深度分析、实操避坑与正规军对比 | 产出 Markdown 文档；兼具紧迫感、专业度与长期价值 |
| **🚦 3. 用户审校定稿 (门禁 Checkpoint)** | **提交中文稿并暂停执行，等待用户/创作者审校** | **核心门禁：严禁在审校确认前抢跑翻译与视觉物料！** |
| **4. 多语言母语级本地化** | 以审校后的中文稿为基准覆盖多语种 | `zh-CN`, `en`, `es`, `pt`, `th`, `vi` 等（含 title, excerpt, seoMeta, 正文） |
| **5. 专属信息图封面 (16:9)** | 依据定稿文案生成专属 16:9 信息图封面 | AI 生图优先，Warm Light Mode 暖色系，每种语言独立生成 |
| **6. 小红书 3:4 爆款图文** | 依据定稿观点生成移动端大字传播物料 | 5 张 3:4 大字卡片 + 100% 纯文本 Emoji 即粘即发文案 |
| **7. 自动化发布与归档** | 写入 CMS / 博客或归档沉淀 | 绑定多语言独立媒体 ID，置顶排位顺延，清理临时脚本 |

---

## 🚦 核心门禁：用户审校中文稿 (Mandatory Review Checkpoint)

⚠️ **最高优先级执行铁律**：
1. **中文初稿完成后必须强制暂停**：完成中文初稿后，AI 必须向用户汇报中文稿内容并**立即停止后续动作**，明确等待用户审校。
2. **绝对严禁提前“抢跑”**：在用户审校定稿前，**严禁提前处理其它语言翻译、严禁提前生成 16:9 封面、严禁提前制作小红书物料！**
3. **审校稿是唯一真相源 (Single Source of Truth)**：用户可能会在中文版中调整核心观点、补充实测真相（如真实价格细节、避坑爆料等）。用户审校定稿后，必须以最终确认的中文正文为唯一准则，再启动后续的外语翻译与视觉设计。

---

## 🔍 第一步：事实核查规范 (Fact-Checking)

收到外部链接（X/Twitter、官方博客、公告、仓库代码）时，**第一动作必须是通过工具真实读取原始文本**，严禁仅凭用户一句话或模糊记忆脑补。

必须核查并明确的核心要素：
1. **门槛与适用人群**：新老用户权益、是否需绑定信用卡、是否有地区/网络限制；
2. **接口形态与协议**：是否开放独立 API Key？若仅限客户端内部使用，严禁在文中编写伪造的 cURL / Python 示例；
3. **时效与清零规则**：确切的截止时间（带时区）以及活动结束后的额度处理机制；
4. **性能与真实架构**：是独立基座大模型，还是套壳路由、多模型编排网关或小参数蒸馏？

---

## 📝 第二步：文章结构标准 (Content Blueprint)

⚠️ **排版与行文铁律：**
1. **严禁在正文中使用任何水平分割线（`---`）**：排版分区必须完全依赖清晰的 Markdown 标题层级（H2 / H3）、引用块（Blockquote）与自然的段落留白，严禁出现水平分割线。
2. **禁止频繁使用括号加注释**：能够融入正文的背景与解释直接以逗号或自然语序顺承，不要通篇频繁使用括号 `（...）` 打断阅读流。
3. **拒绝车轱辘话与冗余说明**：已经交代过的规则、背景与概念不再重复强调，行文紧凑利落，保障高效顺畅的阅读节奏。

### 推荐文章结构：
1. **💡 核心速览 (Key Highlights)**：置顶 4-6 个高亮要点，快速交代事件脉络、核心结论、避坑重点与推荐方案；
2. **🔥 一、事件脉络与官方宣发**：客观梳理事件起因、官方核心卖点与宣发参数，附带官方一手链接；
3. **⚠️ 二、真实社区反馈与实操翻车现场**：列出实测暴露出的一手硬伤（如过度思考、感知延迟极高、身份认知混乱、语法乱码、服务宕机等）；
4. **🛑 三、行业深度剖析与去魅**：
   - 串联同类前车之鉴（如换皮模型、长期挂机的试验品）；
   - 直击三大黑盒（模型真实性黑盒、上下文真实性黑盒、数据隐私与代码安全黑洞）；
   - 明确指出追求性价比合理，但平台与厂商不该以此为由推卸责任；
5. **🛡️ 四、真正的尊重：合格的正规军方案盘点**：对比光明正大、质量过硬、带明确 SLA 与服务保障的成熟主力方案；
6. **💡 五、总结与建议**：精炼金句，呼吁读者理直气壮拒绝劣质产品，守护自己的专注力与时间；
7. **📬 文末转化 CTA**：引导读者订阅 Newsletter 或关注作者社交媒体。

---

## 🌐 第三步：多语言完整本地化标准 (Multilingual Coverage)

面向国际化受众时，多语言版本必须具备**母语级自然表达**，杜绝机械机翻：

- **`zh-CN`** (简体中文 - 核心基准源)
- **`en`** (English - 国际通用标准)
- **`es`** (Español - 西班牙语)
- **`pt`** (Português - 葡萄牙语)
- **`th`** (ไทย - 泰语)
- **`vi`** (Tiếng Việt - 越南语)

每个语言版本必须独立包含：
- `title`：符合当地开发者搜索习惯的高点击率标题；
- `excerpt`：1-2 句精炼的轮播与卡片摘要；
- `seoMeta`：独立的 `title` 与 `description`；
- `content`：地道自然的 Markdown 正文。

---

## 🎨 第四步：独立多语言信息图封面标准 (Localized Covers)

⚠️ **铁律：严禁所有语言复用同一张英文封面！每个语言版本必须拥有原生语言的专属信息图封面。**

### 1. 视觉设计范式 (Infographic Style)
- **尺寸比例**：固定 **16:9**（Landscape）；
- **生图优先级**：**只要有 AI 生图工具，必须全量使用 AI 生图生成，严禁使用 Python PIL 简陋拼接白底图**；
- **主色调与氛围**：**Light Mode 浅色暖黄色调**（Warm Cream `#FFFDF9` 奶油底、Amber Gold `#F59E0B`/`#D97706` 琥珀金边框、深暖浓缩咖啡棕文字 `#451A03`）；
- **核心元素**：
  - 中间悬浮 3D 明亮毛玻璃卡片（Soft Translucent with Drop Shadow），带有清晰的主题大字标题；
  - 核心观点高亮徽章与 2-3 个圆角胶囊标签；
  - 辅以 3D 悬浮金币、光斑光束、高科技微质感边框；
  - 杜绝冷白死白与暗黑混浊色调。

---

## 📱 第五步：小红书爆款图文物料标准 (Xiaohongshu 3:4 Cards SOP)

移动端双列瀑布流中，封面仅占手机屏幕一半宽度，必须遵循**超大字号、精简段落、多图拆解**原则：

### 1. 视觉卡片规范 (3:4 Ratio)
- **尺寸比例**：固定 **3:4**（1080 × 1440 像素）；
- **全量生图**：全套 5 张卡片一律优先使用 AI 生图生成，保持统一的立体光影质感；
- **字号与层级**：
  - **P1 极简超大字封面**：超大字居中（主标题 80~88px），仅保留 1-2 个核心胶囊，杜绝密集小字；
  - **P2~P5 模块化拆图**：每张图只讲一个核心主题（如翻车现场、三大黑盒、正规军方案、行动心态），单图不超过 3 组要点。

### 2. 小红书文案与标题铁律 (Copywriting Rules)
- 📌 **标题字数上限**：**严格不超过 20 个字（字符）**，超出会被小红书瀑布流强制截断；
- 🚫 **零 Markdown 格式铁律（Zero-Markdown Constraint）**：
  - **小红书平台原生不支持 Markdown 解析与渲染**！复制粘贴会导致 `**`、`#`、`-`、`---` 原样裸露；
  - **严禁使用 Markdown 标题标记**（`#`、`##`）：顶部单独以 `【标题】<标题内容>` 标明；
  - **严禁使用加粗标记**（`**加粗**`）：强调信息使用中文【括号】、数字或结合 Emoji；
  - **严禁使用破折号列表**（`- 列表`）：排版必须使用 Emoji 标号（`▪️`、`▫️`、`🔹`、`1.`、`2.`）；
  - **严禁使用水平分割线**（`---`）：段落依靠空行自然留白，或使用整洁的 Emoji 隔断（如 `▫️▫️▫️`）；
  - **文末标签**：空格分隔的 `#话题` 统一排布在最后一行；
  - **文末引导关注**：文末**必须明确提醒读者关注个人账号及主站平台**；
  - **即粘即发标准（Copy-Paste Ready）**：让用户直接全选复制即可发布，零人工清洗成本。

---

## 🛑 历史返工与避坑警示录 (Rework Lessons & Hard Constraints)

1. **事实 100% 真实核验**：数量、参数与端点状态以真实抓取为准，严禁凭模糊记忆臆造；
2. **严禁使用任何水平分割线（`---`）**：纯靠 H2/H3 标题与留白划分章节；
3. **行文杜绝频繁括号注释与车轱辘话**：融入正文顺承表达，概念讲透一次即可；
4. **字体缺失与方框乱码防范**：生图或渲染中泰文、越文必须严格使用原生字形，严禁 Emoji 方框乱码；
5. **多语言封面 100% 本地化**：严禁在其他外语封面上残留中文硬编码字样；
6. **防缓存版本控制**：更新修正图片时追加版本后缀（如 `cover-zh-v2.jpg`），击穿 CDN 强缓存；
7. **真实测评与客观对比**：如实反映缺点与痛点，不为了推广而无原则吹捧；
8. **时效性核查**：所有优惠与限时活动必须确认当前有效，失效活动严禁写入；
9. **小红书 20 字标题与超大字封面**：P1 封面主标题 80px+，文案标题严格小于 20 字；
10. **一次性发布脚本跑完即删**：临时发布脚本执行完毕后及时清理，不污染仓库；
11. **严禁中文未审校即抢跑多语言与视觉（强制门禁）**：中文初稿完成后必须暂停，等待作者确认，严禁提前抢跑外语翻译与生图；
12. **小红书文案严禁 Markdown 格式污染**：100% 纯文本 + 原生 Emoji，无任何 Markdown 语法；
13. **AI 生图优先（Nano Banana First）**：只要有配额，16:9 与 3:4 卡片必须全量使用生图模型绘制，拒绝 PIL 拼图；
14. **移动端响应式与直达链接保底**：正文或周刊排版在手机窄屏下不溢出折行，关键步骤必须提供直达链接；
15. **合作渠道政策动态同步**：已终止的邀请或推荐政策严禁再提，官方正式渠道统一规范使用。
16. **时效性评测与快评文章严禁写入 Seed 库，发布后所有素材必须全量清理**：
    - `seed` 仅用于持久化收录经过认证的真实开放免费 Provider / Model / Endpoint / 核心平台指南；
    - 针对新模型吐槽、避坑快讯、时效性热点评论（非正式收录的长期 Provider/Model），**严禁在 `apps/cms/scripts/seed/` 中新建或注入种子文件**！
    - 发布完成后，**本地的所有草稿 Markdown、多语言翻译文件、本地封面/小红书图片及临时脚本必须全部清理删除，严禁提交进 Git 仓库**，保持代码库纯净。
