# SEO 审计报告模板

使用本模板生成 Markdown 报告。按实际证据删减空段，但不要删除覆盖矩阵里的工具列；没有数据要写明原因，不要留空让读者误认为是 0。

## 标题和范围

```markdown
# 全站 SEO 审计报告

观察日：YYYY-MM-DD（Asia/Shanghai）
数据读取时间：YYYY-MM-DD HH:mm
审计模式：完整审计 / 关键词研究 / Issue 同步
```

说明：

- 纳入的网站、生产域名、对应仓库。
- 永久排除和本轮追加排除；说明“历史采集但当前不纳入”的数据如何处理。
- 是否包含额外发现的生产域名。
- 本轮只读边界，以及用户额外授权的 GitHub issue 写入边界。

## 结论摘要

用 3–8 条按优先级写：阻断问题、最大 CTR 机会、最大排名机会、最值得扩展的关键词/内容集群、最重要的数据缺口。每条引用问题 ID 和网站，不要把猜测写成事实。

## 跨站优先级

| ID | 优先级 | 证据状态 | 已复核 | 网站/URL | 来源 | 证据数字 | 问题 | 修复建议 | 仓库 |
|---|---|---|---|---|---|---|---|---|---|
| SEO-P1-001 | P1 | 已验证 | ✓ 已复现 | example.com/ | GSC + CrUX | … | … | … | owner/repo |

严重度含义：P0=有真实展现的页面丢失索引/流量，或全站级故障；P1=修复明确且影响可观（明显流量/转化损失、CWV 字段未通过等）；P2=重要质量/排名/归因问题；P3=低优先级或需观察。

## Google Trends 研究

记录地区、搜索类型、时间范围和比较组。相关/上升词只是选题线索。

| 主题组 | Query | 地区/类型 | 时间范围 | 平均相对热度 | 最近值 | 峰值/日期 | 相关上升词 | 可执行结论 | 置信度 |
|---|---|---|---|---:|---:|---|---|---|---|

明确写：指数经过归一化，不能解释为绝对搜索量、点击量、市场规模或流量预测。

## GA4、性能和 Ahrefs 证据

分别写自然入口页、sessions/users/engagement/key events；PageSpeed/Chrome 的字段和实验室；Ahrefs 的项目快照、关键词、Top pages、反链和引荐域。不要将不同工具的数字相加。

## 控制台报错复核

| 网站 | 来源 | 报告内容 | 复测 URL | 浏览器 UA | Googlebot UA | 控制台实时检测 | 控制台当前状态 | 结论 |
|---|---|---|---|---|---|---|---|---|
| … | GSC | 5xx ×N | … | 200, 200 | 200, 200 | 通过 | 仍报错，未点验证修复 | 线上正常·控制台待处理 |
| … | GSC | 5xx ×N | … | 200, 200 | 200, 200 | 通过 | 验证通过，报告已消失 | 陈旧 |

每个样例 URL 两种 UA 各测 2 次。伪装 UA 只证明当前线上响应，不证明控制台侧已恢复。只有控制台重新处理且报告消失后才标“陈旧”；线上正常但控制台仍在报的，标“线上正常·控制台待处理”，不进 P0/P1，转入“控制台动作清单”并在下一轮确认。

## 共享代码矩阵

同一个实现问题只写一个问题 ID，再列出受影响站点、源码位置和回归 URL；不要为每个站点复制相同问题。

## 访问缺口与证据边界

单独记录：源码缺失、属性/账号缺失、登录状态不足、工具配额、线上 SSL/超时、指标切换延迟、raw HTML 与渲染 DOM 的差异、Ahrefs 旧快照、Trends 低量样本。说明这些缺口阻止了哪些结论。

## 建议的 GitHub issue（按仓库分组）

| 仓库 | 优先级 | 标题草稿 | 覆盖站点 | 关联既有 issue |
|---|---|---|---|---|

交付时询问用户要开哪些优先级；未获授权前只列草稿。

## 仅需在控制台处理的动作

不涉及代码的动作，例如重新提交 sitemap、在 Bing 开启 IndexNow、确认 GA4 数据流 URL、对“线上正常·控制台待处理”的报错点验证修复或请求重新抓取。只列出，不代替用户操作。
