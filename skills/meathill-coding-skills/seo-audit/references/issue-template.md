# SEO GitHub Issue 模板

只在用户明确授权更新或创建 issue 时使用。先读取完整正文和评论，判断已有 issue 是否覆盖同一工作包；不要用标题关键词命中就直接重复开单。

## 新 Issue 正文

```markdown
## 背景

YYYY-MM-DD 审计发现……

优先级：P1/P2/P3。范围：明确的生产域名和公开页面。

## 问题

用普通语言描述搜索、抓取、内容或转化问题；区分已验证、推断和待复核。

## 证据

- GSC：属性、窗口、query/page、clicks/impressions/CTR/平均位置。
- Bing：属性、实际窗口、关键词、clicks/impressions/CTR/平均位置、sitemap/索引状态。
- GA4：property、窗口、自然入口、session/user/engagement/key event/转化。
- PageSpeed/Chrome：设备、网络、字段/实验室/trace 和实际指标。
- Ahrefs：已有 project 的快照、keywords/top pages、Site Audit、反链/引荐域。
- Google Trends：地区、搜索类型、时间范围、相对热度与相关词；注明不是绝对量。
- 线上/源码：URL、响应/跳转、raw HTML/DOM、绝对源码路径和行号。

不同工具的指标不要合计；数据不可用要明写原因。

## 影响

说明对收录、点击、排名、内容发现、注册/下载/申请或归因的影响。

## 建议工作包

- …

## 验收标准

- [ ] …
- [ ] …
- [ ] 用明确的 GSC/Bing/GA 窗口比较前后结果。

## 非目标

- 不包含……
- 不修改未经授权的外部设置。

## 共享代码/关联工作

列出受影响站点矩阵、源码位置、回归 URL 和关联 issue，避免重复实现或重复开单。
```

## 给既有 Issue 追加证据

优先发一条带日期的顶层评论，保留原正文和讨论历史：

```markdown
## YYYY-MM-DD 追加：Bing Webmaster + Google Trends 证据

### 观测窗口

- Bing：实际显示的 YYYY-MM-DD–YYYY-MM-DD。
- Google Trends：地区、搜索类型、YYYY-MM-DD–YYYY-MM-DD；相对热度，不是绝对量。

### 新证据

| Query/主题 | 来源 | 点击 | 展现/热度 | CTR | 位置/趋势值 | 状态 |
|---|---|---:|---:|---:|---:|---|

### 对原工作包的影响

说明这份证据加强、缩小还是改变了原建议；如果只是低量探索信号，不要升级严重度。

### 后续验收

- …
```

如果正文的范围、验收标准已经过时，才在读取完整正文后更新正文；更新时保留原意，并在变更中说明原因。Issue 写入后重新读取 issue/评论验证 URL、编号、内容和状态。

## 建单判断

- **更新既有 issue**：同一网站/仓库、同一工作包，只是补充新窗口或新证据。
- **新建 issue**：独立目标、独立验收、现有 issue 没覆盖；例如“协议规范化”和“互动小说内容集群”应分开。
- **不建 issue**：只有工具无数据、只有低量趋势、没有明确归属，或网站在最新排除清单中。
- **共享仓库**：同一共享实现只开一个 issue，正文附受影响站点矩阵；不要每个域名各开一个重复 issue。
