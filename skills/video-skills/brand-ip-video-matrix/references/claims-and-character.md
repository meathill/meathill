# 抓口径与 IP 形象

## 一、抓官网口径

### 抓取方式

用 `web_fetch` 直接抓官网首页、产品页、FAQ 页。抓不到就换路径：
产品页常挂在 `/products/<slug>`，也可能在集合页里；有些站点的产品页对无头请求返回的是落地页而非商品页，
遇到这种情况改抓集合页 + FAQ + 首页文案区块，三处拼口径。

抓下来后用 `grep` 把带数字的行挑出来（百分比、体积、升数、天数、微米数），
逐条确认它在页面里的**完整英文措辞**，不要只摘数字。

### 口径清单格式

每条记四样东西：原文措辞、出处 URL、**适用产品线**、这条能支撑什么卖点。

```
Removes up to 99.9% of chlorine, chloramine, certain heavy metals, and 65+ contaminants
  ← https://brand.com/pages/faq  （Filtration 段）
  → 适用：龙头滤芯 Pro（淋浴线是 99%，不可互换）
  → 支撑卖点「硬水 · 65+ 污染物」
```

**"适用产品线"这一列不能省。** 同一个指标在不同产品线上的数值经常不同，
混用就是新的错误宣称。实测踩过的例子：

| 指标 | 龙头滤芯 Pro | 淋浴线 Pro |
|---|---|---|
| 除氯率 | up to 99.9% | up to 99% |
| 最小拦截粒径 | 0.000001mm | 0.00001mm |

两个数字都是官网原文，但**说错了产品线就是错**。
脚本里凡是带数字的句子，都要能对应到清单里某一行的产品线。

### 三条纪律

1. **数字必须能溯源到官网原文**。官网写 "up to 99.9%"，视频里就不能写 "100%"，
   也不能把 "up to" 的限定词丢掉只留数字。
2. **资质型表述照抄限定条件**。临床数据通常带样本量、机构、第三方实验室等限定，
   少了限定词就变成了新的宣称。
3. **官网没有的角度不要补**。比如官网只说"去氯"没提"去水垢"，
   那就只能说去氯；水垢是消费者的推断，不是品牌方的承诺。
4. **同一指标在官网内部冲突时，要单独列一节交给品牌方裁决**，不要自己挑一个用。
   典型形态：同一页脚注写 "up to 98.9% after 10,000L"，
   同页正文写 "above 90% after 10,000 liters"——上线前必须问清楚用哪个。
5. **不同来源的研究不能混用**。临床研究（35 人、第三方实验室）和
   消费者研究（50 人 / 155 人）样本量和方法都不同，
   同一条片子或同一块尾卡里不得并列，也不能互相替换。

### 卖点筛选

一条卖点要同时满足：

| 条件 | 判据 |
|---|---|
| 官网有口径 | 上面清单里能直接引到原文 |
| 能拍成动作 | 能想出一个可视化镜头（滤网截留颗粒、水流穿过滤芯、皮肤特写对比……） |
| 旁白念得完 | 英文旁白 ≤ 6 秒，中文 ≤ 25 字 |

凑不齐就换。宁可 3 个卖点做得扎实，不要 6 个卖点里有一半靠发挥。

**面向消费者的痛点角度 vs 品牌方的宣称角度**是两条不同的线：
官网的 "CLEAR ACNE / REDUCED REDNESS" 可以直接念；
"你的水在毁你的头发"这种是文案创作，不是官网口径，但它是钩子，可以放在**引子句**而不是功效句里。

### 投放侧的合规约束

口径清单之外还有一批"漏了会限流或下架"的约束：AIGC 披露、#ad / Paid Partnership 标注、
音乐商用授权、零售商 logo ≠ 背书、比较级宣称的基准要求。
→ 详见 `platform-compliance.md`

## 二、设计 IP 形象

### 出方向

一次出 3–5 个方向，每个方向一句话描述 + 一张渲染图。描述里要带上：
形态（拟人 / 几何 / 生物）、材质感、配色、与品牌调性的关系。

几何体 + 产品材质（哑光塑料 / 拉丝金属）是安全牌：
它天然贴近品牌产品，且给图生视频模型留了明确的首帧锚点。

### 选定后产出两样东西

**模型表（model sheet）**：正/侧/背视图 + 关键细节特写（面板纹理、眼睛、顶部件）。
用途是把造型细节写进提示词，以及排查"模型把角色做歪了"。

**英雄参考图**：一张 9:16、角色清晰、场景简单的图。
用途是**所有视频首帧的派生来源**——角色一致性靠它继承，不靠提示词维持。

### 角色描述块（写死，之后每次原样粘贴）

```
The character is a simple rounded cube body whose front face is a WHITE SQUARE PANEL
with rounded corners holding a clear acrylic rounded-square frame filled with a fine
grid of tiny round perforations, with two small round dark eyes and a tiny smile printed
on that same white panel, and a short brushed-silver knob cap on top.
It has NO arms and NO hands; the sides of the cube are smooth and plain with nothing
attached to them, and the only parts below are two tiny square feet.
```

写这段时注意几件事：

- **肢体数量要正面写死**。写 "no arms" 不够，要写成"两侧光滑平整、没有任何东西附着，
  下方只有两只小方脚"——模型对"描述形态"比对"否定名词"敏感得多。
- **眼睛的位置写进面板**。写"面板上有两只眼睛"比写"角色有两只眼睛"稳，
  否则模型会把五官挪到身体上，与其它分段不一致。
- **纹理写到具体形状**。"冲孔圆点纹理"比"多孔表面"稳定。
- 配色给 hex 或明确色名（哑光粉蓝 / brushed silver），模型对"哑光 vs 亮面"的响应比色值更明显。

### 命名

品牌词根 + 角色词根（filter + baby → Phoebe）。列 8–10 个候选，
先排除已存在的知名 IP 和常见词（避免生成一堆无区分度的名字）。

### 品牌元素隔离

- 角色本体**不烧 logo**——由客户后期合成，视频里也绝不出现。
- 品牌主色**不进角色本体**。角色用邻近色（粉蓝而不是品牌红），避免后期换色时角色跟着变色。
- 生成画面里**不出现任何文字**：字幕、VI、角标全部后期叠加。
