# 品牌虚拟 IP 短视频矩阵

## Inputs to collect

开工前先确认，缺哪项就问哪项（不要用默认值硬上）：

| 输入 | 为什么需要 | 缺省建议 |
|---|---|---|
| 品牌官网 / 产品页 URL | 功效数字的唯一合法来源 | 无 → 必须先要 |
| 目标市场与受众 | 决定语言、口吻、场景、审美 | 美区 25–45 岁女性等 |
| 要几个卖点 / 几条片子 | 决定矩阵规模与工时 | 5 个卖点 |
| 平台与时长 | 决定安全区、字幕位置、编码 | 9:16 / 33s + 15s |
| 角色形象：已有定稿 / 从零设计 / 用户给参考图 | 决定流程从第 2 步还是第 1 步开始 | 从零设计 |
| 生成额度：图片生成 / 图生视频 / 文生视频哪些可用 | 决定首帧从哪来、失败怎么降级 | 开工前先探一次额度 |

## Procedure

### 1. 抓口径（官网是唯一真源）

逐个抓官网首页与**每条产品线**的产品页，把可对外的功效表述连同
**原文措辞、出处 URL、适用产品线**记下来。同一指标在不同产品线上数值经常不同
（实测：龙头线 99.9% / 淋浴线 99%，粒径 0.000001mm / 0.00001mm），说错产品线就是错。

任何写进视频的数字都必须能在这份清单里找到原文；找不到就换成更保守的官方表述，或直接砍掉这个卖点。
不要从记忆或行业常识推数字——品牌方的合规口径以官网为准，客户端出现官网没有的数字就是事故。

官网内部口径互相冲突时（同一页两处数值不一致），单独列一节交给品牌方裁决，不要自己挑一个用。

→ 详见 `references/claims-and-character.md`

### 2. 定 IP 形象，并把硬约束写死

出 3–5 个形象方向，渲染成图后选一个。选定后产出一份**模型表**（model sheet：正/侧/背、配色、材质细节）
和一张**英雄参考图**，后续所有镜头都从它派生。

选定当场把以下内容写成一段**可复制的角色描述块**，之后每一个视频提示词都原样粘贴这段：

- 形态与比例、配色（哑光/亮面）
- 正面面板的形状、框的形状、纹理（冲孔/网格/同心圆）
- 眼睛与嘴的位置与样式
- **肢体数量**（没有手臂就写死"没有手臂"，这是最容易被模型违反的一条）
- 头顶件 / 配件

角色本体不烧品牌 logo，品牌主色不进角色本体——由客户后期合成。

命名取品牌词根 + 角色词根，先排除已存在的知名 IP。

→ 详见 `references/claims-and-character.md`

### 3. 写卖点矩阵规格（一份文件当唯一真源）

建一个规格文件（Python 常量或 JSON）存每个卖点的：标题、官网口径、首帧路径、
10s 与 6s 两段的中英文提示词、两条英文旁白与字幕文案、时间轴微调。

卖点必须同时满足三条才成立：**官网有口径**、**能拍成一个动作**、**旁白 15 秒内念得完**。
一条卖点凑不齐这三条就换掉，不要靠发挥数字硬凑。

A 段（亮相）、C 段（收束）、D 段（品牌板）所有卖点共用；只有 B 段按卖点变化。

### 4. 生成镜头（角色一致性的根：首帧继承）

**首帧必须含角色。** 只要角色是模型"凭空生成"的（图生视频的第一帧里没有它），
模型就会自己捏一个：常见的失败是长出手臂、丢掉眼睛、把面板形状改掉。
让模型从参考图继承造型，比在提示词里反复强调要有效得多。

提示词用四块结构：角色描述块（粘贴第 2 步那段）+ 动作块 + 风格块 + 禁止项。
禁肢要写成"cube 的两侧光滑平整、没有任何东西附着，下方只有两只小方脚"，
写 "small / tiny / no arms" 模型基本无视。

续接段（第二段画面）的首帧必须取自**同一条第一段视频的末帧**，
且第一段要以中景或全景收尾——从特写末帧接续会让模型丢失整体轮廓并臆造解剖结构。

提示词里避免让角色"互动"的动词（patting / holding / tapping / leaning over），
这类动词会显著提高长出手臂的概率。

生成后逐条抽帧质检：8–9 帧拼成一张 strip 看整体，再放大看角色的脸和侧面。

→ 详见 `references/video-generation.md`

### 5. 声线与音乐床

用支持"角色设计 + 克隆"的 TTS（小米 MiMo-V2.5-TTS 已验证）：
先用 voicedesign 生成一条**母版**声音，再用 voiceclone 把各条台词复刻到这条母版上——
voicedesign 不接受参考音频，每次调用都会重新设计一条嗓子。

给复刻的指导词必须简短：冗长的角色/情绪描述会把语速拖慢近一倍，短指导只增加约 0.6 秒。

音乐床批量生成几版让用户试听选定，归一化到 RMS -18 dB 再进混音。

→ 详见 `references/voice-and-music.md`

### 6. 装配成片

时间轴骨架：固定 A 段 + 每卖点独立 B 段 + 固定 C 段 + 固定 D 段，
再另出一条只含 B 段的短版，便于横向比较卖点本身。

旁白之间不许重叠；字幕窗口按旁白实际时长自动延长；短版的时间线要与完整版严格对齐
（音乐与音效按 offset 裁切，不要另起一套混音）。

字幕用 PIL 渲染成 PNG 再 overlay（多数 ffmpeg 编译没带 libfreetype/libass，drawtext 和 subtitles 都不可用）。

编码固定 H.264 High@4.0 / yuv420p + AAC-LC 48 kHz 立体声，响度 -14 LUFS、True peak ≤ -1.5 dBFS。

用 `scripts/assemble.py`（规格 JSON 驱动）跑整条流水线，`scripts/make_subtitle.py` 出字幕层。

→ 详见 `references/post-production.md`

### 7. 质检与评审包

逐条核对：编码参数、时长、响度、字幕命中（抽帧确认窗内有字、窗外无字）、
旁白不重叠、角色无手臂无漂移、生成画面里没有任何文字。

再核一遍投放侧合规：AIGC 披露标注、#ad / 付费合作标注、音乐商用授权、
限定词是否也进了字幕（观众常静音观看）、零售商 logo 有没有被当成背书。

产出一份评审文档：逐条脚本、官网口径出处、实测规格、评审要点、**已知限制如实写**，
再打一个 zip（成片 + 文档 + 关键帧总览图）方便直接发给同事。

→ 详见 `references/post-production.md` 与 `references/platform-compliance.md`

## Output contract

| 产物 | 位置约定 |
|---|---|
| 卖点规格唯一真源 | `selling_points.py` / `spec.json` |
| 角色参考图与各卖点首帧 | `ip-concepts/` |
| B 段原始素材 | `videos/sp/` |
| 成片矩阵 | `videos/matrix/<key>-1080.mp4`（完整版）+ `<key>-sp15-1080.mp4`（卖点短版） |
| 旁白与音乐床 | `audio/voices/`、`audio/beds/` |
| 评审文档 | `filterbaby-<brand>-selling-point-matrix.md` |
| 分享包 | `filterbaby-<brand>-review-pack.zip` |

成片规格：1080×1920 / H.264 High@4.0 / yuv420p / 24 fps / AAC-LC 48 kHz 立体声 /
-14 LUFS / True peak ≤ -1.5 dBFS。

## Failure handling

| 症状 | 原因与对策 |
|---|---|
| 角色长出手臂、丢掉眼睛、面板变形 | 首帧里没有角色。把标准造型帧作为首帧，别只靠提示词强调 |
| 角色在续接段里转了 180° 或背对镜头 | 续接段首帧取自特写末帧。改从同一条视频的中景末帧取，并锁死"always facing the camera" |
| 画面出现爆炸图 / 零件飞散 | 提示词里写了"拾起 / 拆解 / 推开"类动作。改成物体并排静置、镜头绕行 |
| 图片生成 402 / 额度耗尽 | 降级：用已有素材本地裁切、抽帧派生首帧。角色 100% 一致但场景多样性受限，需在评审文档里写明 |
| 文生视频只出"通用蓝色方块" | 换图生视频通道，纯文本生视频给不出有辨识度的角色 |
| TTS 四条台词音色不一致 | voicedesign 不支持参考音频，必须先做母版再 voiceclone 复刻 |
| TTS 语速突然变慢一半 | 指导词太长，砍到一行以内 |
| 字幕完全没出现 | ffmpeg 没有 drawtext/subtitles 滤镜，改用 PIL 渲染 PNG 再 overlay |
| 成片播放时声音静音 | loudnorm 内部升采样到 192 kHz，ffmpeg 按 96 kHz 封装 AAC。滤镜链里补 `aresample=48000` 并加 `-ar 48000 -ac 2` |
| ffmpeg 跑完不退出 | overlay 配 `-loop 1` 的图片输入是无限流，输出侧加 `-t` 和 `-shortest` |
| 字幕把画面顶成 yuv444p | filter 链末加 `format=yuv420p`，编码参数加 `-profile:v high -level 4.0 -pix_fmt yuv420p` |

## Examples

**Input**：「我们有个净水品牌，想做一个虚拟 IP 形象，先出 3 条不同卖点的短视频给内部评审。」

**Output**：
1. 抓官网得出可对外口径清单 → 挑出除氯 / 硬水污染物 / 皮肤三个卖点
2. 出 4 个形象方向 → 选定「立方体小水人」，产出模型表与英雄参考图，冻结"无手臂"等硬约束
3. 写规格文件，三个卖点各配 10s + 6s 两段提示词与中英旁白
4. 每段首帧都用**含角色的标准帧**（角色继承来源）→ 抽帧质检确认无手臂、脸在位
5. 用一条母版声线克隆三条旁白，音乐床选一首
6. 装配出 6 个文件（3 条完整版 + 3 条卖点短版），全部通过编码与响度检查
7. 输出评审文档 + zip，文档里如实注明"本轮画面为 768P 上采样，首帧受图片额度限制"

## Windows (win32) platform notes

- `python3` 换成 `python`（或 `py -3`）；`bash scripts/qc_video.sh` 用
  `bash`（Git Bash）或把脚本里的 `grep` 换成 `Select-String`。
- 字幕脚本默认按 macOS 字体路径找字，找不到会回落到 DejaVu Sans Bold 与
  `C:/Windows/Fonts/arialbd.ttf`，都不存在时会明确报错而不是静默出字形不对的图。
- ffmpeg 滤镜链里的 `|`、`;` 在 PowerShell 里需要加引号传给 `& ffmpeg`；
  建议把命令写成 `.ps1` 脚本而不是直接内联执行。
- 图生视频与 TTS 的接口调用走 Python（`urllib`），与平台无关。
